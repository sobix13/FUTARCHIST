FUTARCHISTUser and deployment guide · Version 2.1

Keep information and work in the right workspace

FUTARCHIST collects project information and fundraising details, manages contact with representatives, and organizes internal teams, programs and follow-ups. It serves individual admins, agencies, hosts and management teams. Its scope extends beyond radio guests.

English is the only interface language. The bot, forms, admin panels, errors and documentation use English. There is no language selector. People enter their own information. Filters use explicit criteria, and invitations require a preview and confirmation. No AI services are used.

Start here

1. Choose a workspace. Use a personal space for individual work or a team space for shared work. 2. Collect information. Create an Access code and share its intake link. 3. Review the case. Check General and Raise, record the status, assignee and follow-up. 4. Plan the next action. Use Tasks, Programs and confirmed Invitations.

1. Submit information as a project representative

  1. Start the bot. Enter the access code supplied by your contact, or open their private intake link. The alternative command is /activate CODE.
  2. Review the destination workspace and intake route. Agree to continue.
  3. If the route supports both branches, choose General information, Raise review or Both.
  4. Use the buttons and short text replies. Skip optional questions when needed. Review your answers before submitting.
  5. Press Submit. Consent to receive future DM invitations is a separate choice.

Use /resume to continue a draft, /back to return to the previous question, and /cancel to discard the draft. Discarding a draft leaves submitted cases unchanged. Save and leave retains your answers.

/projects lists your submissions. Editing requires an active code and route for the same workspace. If someone updated the case while you were editing, reopen it before saving.

/stop stops DM invitations. Replies to case-related questions remain available independently. /support opens the two support contacts.

General questions

The seven questions cover project name, areas, reason for building, product stage, network environment, product/demo URL and social links or team contacts. Name, areas, stage and environment are required. Motivation, URL and socials are optional.

Product stage includes Idea, Building, Beta and Live product. Devnet, Testnet and Mainnet are separate network environments. A beta product might run on Mainnet.

Raise questions

Questions cover the current or most recent raise, platform, currency, target, amount received and consideration of MetaDAO. A retry plan is requested for unsuccessful or partially funded raises. Amount questions depend on raise status and currency. Zero means nothing received. A skipped answer means unknown.

No current plan does not require a platform or amounts. Choose OTHER for currencies outside the list, then enter a code such as GBP. The form records the latest/current raise, not separate historical rounds.

3. Intake routes and private access codes

Open Access codes. Create a route with a name, form purpose and initial assignee. The creator becomes its source admin. Share either the code or its ?start=intake_CODE link.

Edit its name, activation limit, optional Telegram ID restriction and UTC expiry. An empty limit or expiry means unrestricted capacity or duration. Each activation is tied to a person. A restricted code works only for its assigned Telegram ID.

Open Manage code access to revoke or restore one person's access. Rotation disables the old code and creates a fresh one while preserving cases and source history. Give the new code to people who need renewed access. Suspension, expiry, inactive assignees and workspace access are checked again before submission.

The sender's code routes information into a specific workspace. It does not grant admin access. Public intake is disabled in live mode.

4. Cases, assignments, notes and replies

Open Cases and select a project. General information and raise information appear separately. Each review branch records its source admin, current assignee and status: New, Under review, Follow-up, Accepted or Closed. Source tags retain the original numeric ID and name.

Use Edit general information or Edit raise information to change permitted fields. The guest identity and source stay unchanged. Assignment requires its own permission and an eligible member. Concurrent edits using an outdated version are rejected.

Internal notes remain private to authorized reviewers. A question to the representative is sent through the bot, with a personal reply link. The reply returns to the same case and branch. Previously delivered messages and replies are not overwritten. Add a correction note when needed.

Authors with write access edit their own internal notes. Superadmins edit or delete other internal notes. Activity records who performed each operation. Read-only members receive no editing controls.

Superadmins archive cases, restore them or permanently delete an archived case after confirmation. Archived cases have no editing controls. Deletion removes stored case relationships and related database content. Old backups and previously delivered Telegram messages remain outside the deletion.

5. Filters and saved views

Filter by search text, areas, product stage, network, review branch and status, assignee, source admin, raise status, retry plan, MetaDAO consideration, platform, currency, target and amount received. Apply a criterion alone or combine several.

Multiple selected areas match any selected area. Different filter criteria apply together. Platform matching is exact. Amount filters require a currency and never compare different currencies. Missing amounts are not treated as zero.

Raise filters require raise read permission. Saved views belong to you in the selected workspace. Save, apply or delete a view. The same filters also determine invitation recipients and linked project export rows. Workspace-wide datasets retain their documented scope.

6. Programs, participation and outcomes

Create a program with a title, kind, topic, timezone, time, description and status. Types include Radio, Roadshow, Podcast, Meeting, Campaign, Raise and Other. Programs record past work and upcoming plans.

Link projects from the same workspace. Record participation as Planned, Invited, Confirmed, Attended or Declined. Remove a project from a program without deleting its case.

Record outcomes after a program. Program entries do not automatically send invitations. Use Invitations for a separate preview and confirmation. Raise programs require the corresponding financial permissions.

Superadmins archive and restore programs. This version does not sync external calendars or schedule reminders.

7. Tasks and follow-ups

Create a task with a title, branch, assignee, optional due date and optional project or program link. Status options are Open, In progress, Done and Cancelled. Links must belong to the same workspace and a compatible branch.

Use explicit timezones. Task views show due dates in UTC. Changing an assignee requires assignment permission. Updating a task without changing its assignee uses the relevant write permission.

Superadmins archive and restore tasks. Due dates are stored and shown. Automatic reminder delivery is separate future work.

8. Invitations and group connections

Choose recipient filters in Cases, then open Invitations. Enter a topic, time and message template. Supported variables are {project}, {topic}, {when} and {sector}. Personalization uses those explicit fields.

Create a preview. Review the destinations, individual messages and unavailable recipients before confirming. Each destination receives one invitation. Recipients and text are fixed at preview time. A filter change needs a fresh preview.

A project needs either a verified connected group or a representative who opted into DM invitations. The bot does not start private conversations with people who have never started it. Consent and access are checked again before delivery.

To connect a group, create a connection code from the case. Add the bot to that group. The code creator or project representative sends /bind CODE as a group admin. The single-use code expires in 10 minutes. Telegram group permissions are verified before binding.

The bot does not collect regular group conversations. A project and group each have one active connection. Disconnecting stops future group invitations. A group invitation reply link belongs to the project representative.

Replies are Yes, No or Later. Cancelling a campaign stops its remaining queued deliveries. It does not recall delivered messages. Check any Uncertain delivery in the destination chat before resending.

9. Excel, CSV and dataset exports

Open Exports in the dashboard or use /export in Telegram. Select Projects, Branches and assignments, Raise, Notes and replies, Programs, Tasks, Invitations, Activity, Routes, Groups or All permitted datasets.

XLSX uses separate worksheets for multiple datasets. A single CSV uses UTF-8 with a BOM. Multiple CSV datasets are delivered in one ZIP. Formula-like CSV text is escaped, and XLSX text remains literal.

Read permissions control exported content. Financial data is excluded without raise access. Route codes and private login credentials are not exported. Permissions are checked again before a queued Telegram export is generated and delivered.

Current case filters apply to projects and their linked records. Workspace-wide route/group metadata and unlinked programs or tasks retain their workspace scope. Use a narrower filter for large collections. The per-table limit is 100,000 rows and the generated file limit is 20 MB.

10. Editable bot text and questions

Superadmins open Bot text to edit the welcome message, help, invitation template and question wording. The same controls are available in Telegram and the browser dashboard.

Custom question text is used in English-only guest forms. Editing wording preserves field types, conditional questions and validation. A custom schema or question builder is future work. Invitation templates accept only the four supported variables.

Concurrent edits require the current text version. Public bot name, description and English command menus are set using the deployment command --configure-bot.

11. Health, troubleshooting and bounded recovery

Superadmins use /health or the health page. It shows database integrity, references, disk space, worker heartbeats, delivery queues, failed updates and recorded incidents. Failed update IDs are available for review.

StateNext action
PendingWait for the queued job. Avoid creating a duplicate.
SentThe API confirmed delivery.
FailedReview the error, permissions and destination.
UncertainCheck the Telegram chat before resending.
StaleReview worker liveness and the VPS.

Safe recovery and /repair clean expired state and requeue eligible transient group-verification failures. They do not rewrite code, damaged business records or unknown delivery outcomes.

Retry a failed update only after reviewing its cause. Its failed transaction was rolled back. Acknowledge incident records superadmin review. It does not resolve the underlying problem.

Create verified backup makes a consistent local database snapshot. Database files are not sent to chat. Restore requires stopped processes and a fresh destination on the VPS.

Inbox, outbox and maintenance use independent workers. A failed update or file export does not stop later jobs. The suggested deployment separates bot and web processes. The browser remains available during a Telegram connection failure, and /manage remains available during a web failure. Shared database, disk or full network failure still requires infrastructure repair.

12. Browser dashboard and Mini App

/manage works inside Telegram. With HTTPS configured, open the panel button or request a personal browser link with /panel. The link is single-use and expires in 5 minutes.

Mini App identity is verified on the server. Typing an ID or username into a browser never grants admin access. Use the workspace selector to switch spaces. Lists and filters follow the selected workspace.

On a connection failure, use Refresh or the native Telegram fallback. If a save response did not arrive, check the current status before repeating it. A request might have been stored before the response failed.

All built-in copy uses English and left-to-right layout. Dates and numbers use English formatting. User-entered records stay as entered. Upgrading from the earlier build converts recognized built-in defaults and preserves custom copy and form answers. Previously delivered messages remain part of their original history.

13. Local execution and VPS deployment

python3 -m venv .venv
.venv/bin/python -m futarchist --demo

Open http://127.0.0.1:8765 and /emulator. Sample accounts are superadmins 1 and 4, admin 2, read-only member 3 and representatives 101 and 102. No real Telegram messages are sent.

For live operation, copy .env.example to .env. Set BOT_TOKEN, OWNER_TG_ID 313342234, both SUPER_ADMIN_IDS and BOT_USERNAME FutarchistBot. When replacing the test bot, update token and username. The real token is excluded from source and deliverables.

.venv/bin/python -m futarchist --env .env --check-bot
.venv/bin/python -m futarchist --env .env --configure-bot
.venv/bin/python -m futarchist --env .env --mode bot
.venv/bin/python -m futarchist --env .env --mode web --port 8765

Leave APP_URL empty for native Telegram use. For the panel, set an exact HTTPS origin with no path. HTTP stays on loopback behind nginx. Deployment files include independent systemd units, nginx configuration, a health probe and backup tools. Follow extensions/DEPLOY.md. VPS installation was not performed in the build environment.

Schema 1 upgrades take a backup before migrating to schema 2. Keep the original superadmin ID in the new owner list. Unknown schemas are rejected. Process locks prevent duplicate polling workers for one database. This release does not support SQLite on network shares or multiple VPS hosts.

The separate test report records backend, permissions, HTTP, Telegram-shaped simulation, DOM and real Bot API evidence. A simulator is not an official Telegram client. DOM checks do not verify visual rendering.

Before broad use, test both real superadmins, restricted codes, all three form purposes, a read-only team member, reassignment, questions/replies, opt-out, a real group, invitation confirmation, file downloads, archive/restore and code revocation mid-draft.

Open the HTTPS panel in Telegram on iOS, Android and desktop and in an ordinary browser. Check English layout, 390px width, focus, dialogs, logos and file downloads. The report identifies checks blocked by the build environment. Production load, disk failure and independent security review are separate acceptance work.

Later work includes importing the previous website, calendar sync, reminders, multiple raise rounds, attachments and PostgreSQL. These are listed separately in the operations package and are not active in this release.
